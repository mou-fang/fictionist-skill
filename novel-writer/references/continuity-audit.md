# Continuity Audit

Use this reference when checking plot holes, revising outlines, preserving canon, or diagnosing why a story feels illogical.

For file-backed projects, run the audit against project files first, then against draft prose. The core files are the source of truth unless the user says the draft should override them.

## Audit Order

Check in this order:

1. Canon facts: names, ages, relationships, skills, locations, rules, timeline, injuries, secrets.
2. Cause and effect: whether each major event follows from previous pressure or choice.
3. Motivation: whether each major action has desire, fear, incentive, misunderstanding, or constraint.
4. World rules: whether magic, technology, law, money, travel, communication, and social power stay consistent.
5. Setup and payoff: whether solutions, reveals, betrayals, kisses, deaths, and powers are planted.
6. Reader promise: whether the genre pleasure is being delivered without breaking tone.
7. File sync: whether new facts in draft prose were written back to canon, timeline, promise ledger, and decisions log.

## Plot Bug Checklist

Flag any issue where:

- A character ignores an obvious solution with no constraint.
- A rule works differently only when convenient.
- A secret could be revealed by a simple action everyone would naturally take.
- The timeline has impossible travel, recovery, aging, study, pregnancy, investigation, or communication speed.
- A character's skill appears or disappears without setup.
- The antagonist stops acting so the protagonist can win.
- A coincidence solves the problem instead of complicating it.
- A clue appears after the reveal instead of before.
- A romance conflict relies only on avoidable noncommunication.
- The climax is won by new power, new information, or a third party not properly seeded.
- A continuation contradicts a project file because the assistant wrote from memory instead of rereading.
- A user-proposed change is treated as canon before the user confirms its impact.

## Severity Labels

Use these labels when reporting issues:

- Critical: breaks the story's central logic or ending.
- Major: weakens a key arc, reveal, relationship, or world rule.
- Minor: causes confusion but can be fixed with a line, beat, or small setup.
- Opportunity: not a bug, but a chance to make the story fresher, sweeter, tighter, or more emotional.

## Fix Strategy

Prefer fixes that preserve canon:

- Add pressure instead of changing personality.
- Add a constraint instead of making characters foolish.
- Seed the solution earlier instead of removing payoff.
- Turn coincidence into a trap, cost, or character choice.
- Make both sides of a romance conflict partly right.
- Use existing objects, rules, debts, promises, or secrets for the fix.

When multiple fixes are possible, offer two or three options with tradeoffs:

- Minimal patch: smallest change to restore logic.
- Dramatic patch: stronger conflict, higher cost, or better payoff.
- Freshness patch: preserves logic while making the premise less familiar.

## Resume Audit

Before writing the next chapter in an existing project, answer:

- What was the last completed chapter or scene?
- What does the protagonist currently want?
- What is the immediate obstacle?
- What secrets or promises are active?
- What relationship state cannot be reset?
- What world rule or constraint matters in the next scene?
- What chapter hook or unresolved pressure must be honored?

If any answer is missing from files, update the relevant core file or ask a short non-spoiler question.

## Canon Change Audit

When the user adds or changes a setting:

- Check whether it conflicts with canon, timeline, character motive, world rules, relationship status, genre promise, or planned payoff.
- If it conflicts, propose a minimal patch, dramatic patch, and freshness patch.
- Keep rejected options in the decisions log only if they help explain future choices.
- Never rewrite already established facts silently to make a new idea fit.
